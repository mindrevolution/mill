# Generate Label Map

Analyze repository labels and generate `.mill/label-map.yaml` for autopick scoring.

## Input

`{{LABELS_JSON}}` — Output of `gh label list --json name,description,color`

## Workflow

### 1. Parse Labels

Group labels by likely purpose based on name patterns and descriptions.

### 2. Map to MILL Categories

#### Type Mapping
Match labels to intent types:

| MILL Type | Common Patterns |
|-----------|-----------------|
| security | security, vulnerability, cve, auth-*, *-injection, xss |
| bug | bug, defect, error, fix, broken, issue, problem |
| feature | feature, enhancement, new, add, request, improvement |
| task | task, chore, refactor, docs, documentation, maintenance, tech-debt |

#### Impact Mapping
Match labels to priority/impact:

| MILL Impact | Common Patterns |
|-------------|-----------------|
| high | critical, urgent, priority:high, p0, p1, blocker, important, must-have |
| low | low, nice-to-have, priority:low, p3, p4, minor, trivial, wontfix-candidate |

#### Complexity Mapping
Match labels to size/effort:

| Complexity (1-5) | Common Patterns |
|------------------|-----------------|
| 1 | trivial, quick, size:xs, size:s, good-first-issue, small |
| 2 | easy, size:sm |
| 3 | medium, size:m, moderate |
| 4 | large, size:l, involved |
| 5 | complex, size:xl, epic, major, architectural |

#### Exclude Labels
Labels that indicate issue should be skipped:

| Exclude | Common Patterns |
|---------|-----------------|
| yes | wontfix, duplicate, invalid, question, discussion, backlog, deferred, on-hold, icebox, later, stale, spam |

### 3. Generate YAML

Output format:

```yaml
# Auto-generated by mill init
# Edit to customize label mappings for your repository

type_mapping:
  security:
    - security
    # add repo-specific labels
  bug:
    - bug
  feature:
    - feature
    - enhancement
  task:
    - task
    - chore

impact_mapping:
  high:
    - critical
    - priority:high
  low:
    - low
    - nice-to-have

complexity_mapping:
  1:
    - good-first-issue
    - trivial
  3:
    - medium
  5:
    - complex
    - epic

exclude:
  - wontfix
  - duplicate
  - invalid
  - question
  - backlog
  - deferred
  - on-hold
```

### 4. Handle Edge Cases

**No labels in repo:**
Generate minimal default map with MILL's standard labels:

```yaml
# No custom labels detected — using MILL defaults
type_mapping:
  security: [security]
  bug: [bug]
  feature: [feature]
  task: [task]

impact_mapping:
  high: [impact:high]
  low: [impact:low]

complexity_mapping: {}
exclude: [backlog, deferred, on-hold]
```

**Ambiguous labels:**
If a label could match multiple categories, prefer:
1. Type over impact (e.g., "critical-bug" → bug, not high)
2. More specific match (e.g., "auth-bug" → bug)

**Unknown labels:**
Labels that don't match any pattern → ignore (don't include in map).
User can manually add them later.

## Output

Write the YAML content. CLI will save to `.mill/label-map.yaml`.

## Example

Input:
```json
[
  {"name": "bug", "description": "Something isn't working"},
  {"name": "enhancement", "description": "New feature or request"},
  {"name": "P0", "description": "Critical priority"},
  {"name": "size/L", "description": "Large task"},
  {"name": "wontfix", "description": "This will not be worked on"}
]
```

Output:
```yaml
# Auto-generated by mill init

type_mapping:
  security: []
  bug:
    - bug
  feature:
    - enhancement
  task: []

impact_mapping:
  high:
    - P0
  low: []

complexity_mapping:
  4:
    - size/L

exclude:
  - wontfix
```
